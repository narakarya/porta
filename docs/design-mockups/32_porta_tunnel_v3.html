Tunnel section — v3 (progressive disclosure)

Supersedes 09 and 11. The shipped panel stacks 13 blocks in one column while a tunnel is live: a Connected badge, the URL, an amber “Accessible hosts” list, a green “Reachable” bar, an amber drift banner with its own Reconnect, the mode toggle, the tunnel picker, the hostname field with two lines of helper text, a second amber host list saying the same thing as the first, an Access hint, the alias-domain block with a checkbox, an auto-start checkbox, and a Disconnect/Reconnect row. Four of those blocks report status, two report the same hosts, and two are Reconnect.

v3 keeps every feature and every command. It changes when each one is on screen.

Rules this design holds to

  1. One status surface. Provider, live URL, reachability, and routing collapse into a single strip. Nothing else on the panel reports status.
  2. The host list appears once, and belongs to a context. In the strip it means what is live right now; inside Settings it means what Connect would change it to. Never both at once — that pairing is what made a stale field look like a live one.
  3. Settings are collapsed while a tunnel is live. The resting state of a working tunnel is four lines, not a form. Opening Settings is one click and nothing is hidden behind a mode change.
  4. One Reconnect. It lives in the Settings footer, next to the edits that need it. The strip states the drift and links to it — it does not offer a second button that does the same thing.
  5. Amber means “you need to act”. Informational host lists lose their amber; it now only marks drift, unreachable, and setup-required.
  6. Advanced stays folded. Alias domain, Host rewrite, and auto-start sit under one Advanced disclosure with a summary of what is set, so a non-default is never invisible.
